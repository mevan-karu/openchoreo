## Purpose
> Briefly describe the problem or need driving this PR and how it resolves the issue. Include links to related issues if applicable.

PR #4462 built the audit framework but wired it to only **12 of 114** state-modifying REST routes, with the definitions table maintained by hand and nothing stopping the next mutating route from landing unaudited.

This PR closes coverage on both REST and MCP and makes that closure structural: audit definitions are now **generated from the OpenAPI spec** and regenerated by `make code.gen`, so a new route either gets a definition or fails `code.gen-check`. Every state-modifying operation must be audited or carry a written exemption reason, enforced by a build-time gate. It also adds authentication-rejection auditing, `/exec/`/wirelogs coverage, and a `project`/`component`/`resource` hierarchy on every record.

Closes #4460.

**Epic:** [#3343](https://github.com/openchoreo/openchoreo/issues/3343) · **Proposal:** [Discussion #4396](https://github.com/openchoreo/openchoreo/discussions/4396) · **Follows:** [#4462](https://github.com/openchoreo/openchoreo/pull/4462)

## Approach
> Summarize the solution and implementation details.

- **Generated definitions** (`tools/auditgen` → `definitions.gen.go`) — replaces the hand-written table. Derives one `OperationDef` per non-GET spec operation (112, plus 2 hand-declared non-spec routes = 114 total), wired into `make code.gen`.
- **MCP binding table** (`audit/mcp_bindings.go`) — 69 tools / 90 binding keys mapping tool + scope + resource-arg onto a REST operationId, since that mapping isn't mechanically derivable. Includes alias support for deprecated tool names.
- **Exemptions with mandatory reasons** (`audit/exemptions.go`) — 2 REST (an authz-decision read, an HMAC webhook), 8 MCP (schema-lookup tools that mutate nothing) — each checked by the gate to still name a live operation.
- **Coverage gate** (`TestAuditCoverage`, 7 assertions) — every mutating REST op and non-read-only MCP tool is defined/bound or exempted, every binding/exemption points at something real, no duplicate bindings, tool count pinned. A companion AST check (`TestHandlers_BodyCarriedCreatesCallSetResource`) statically verifies every body-carried create calls `audit.SetResource`.
- **Authentication rejections** — a new outer `NewUnauthenticatedMiddleware` distinguishes `unauthenticated` (401 / no subject) from `denied` (403 / policy refusal), composed above the existing middleware so it sees rejections auth short-circuits before `next` runs. Exactly-once emission is tracked via a shared marker, tested including under panic.
- **`/exec/` and wirelogs** — audited despite sitting outside the OpenAPI-generated mux (no operationId to cross-reference). New `Operation.NotInOpenAPISpec` lets these skip pattern-map construction while still flowing through the coverage gate and matrix.
- **Resource identity fixes** — `SetResource` replaces rather than merges the whole `*Resource`, so a call omitting `Namespace` was dropping it on success. Fixed across 78 handler call sites, also backfilling `Resource.ID` from the K8s UID.
- **Resource hierarchy** — a new `Hierarchy` (`Namespace`/`Project`/`Component`/`Resource`) is captured once at `AuthzChecker.Check`, before the PDP evaluates, so it's present even on a denial, on both REST and MCP. MCP additionally pre-seeds a claimed hierarchy from call arguments to cover filter-layer denials that never reach `Check`. A real ordering bug — an early "first Check wins" rule silently dropping `project`/`component` when a precondition lookup ran its own `Check` first — was caught by testing against a live k3d cluster (no unit test caught it) and fixed to last-write-wins.
- **`X-Request-ID` hardening** — `logger.Middleware` now requires a valid UUID, generating one otherwise, so the access log and audit envelope always agree on one ID.
- **Coverage matrix** (`make audit-coverage-matrix` → `docs/audit/coverage-matrix.md`) — every audited operation/tool, every exemption and reason, and a *Known non-events* section for gaps below.

### Verification

`make lint`, `go build ./...`, and the full audit/config/mcp/handler test suites are green; `make code.gen` produces no diff. New tests cover the coverage gate, the AST guard, exactly-once auth-rejection emission, `/exec/`/wirelogs, MCP alias merging, and the resource hierarchy (including a regression test for the ordering bug above).

## Remarks
> Add any additional context, known issues, or TODOs related to this PR.

Known gaps, documented in code and in the coverage matrix's *Known non-events* section rather than left to be rediscovered:

- **`resource.name` (and the resource hierarchy) on the 42 body-carried creates is success-only** — nothing reads the request body before the handler runs, so neither is available on a denied/failed create. Needs request-body extraction (a P3 dependency).
- **`?filterByAuthz=false` on MCP records a refusal as `failure`, not `denied`** — the go-sdk discards the error identity before the middleware sees it. A `results: [denied]` query silently misses these.
- **`source_ip` is a hint, not forensic evidence** — read from `X-Forwarded-For`/`X-Real-IP` with no trusted-hop count, and unobtainable at all for a direct (non-proxied) MCP client.
- **Live `/exec/`/wirelogs verification through a real hijacked connection is outstanding** — only `Flusher` pass-through is tested.
- **Audit output format is still unresolved** — under a text log handler, audit records ship unparseable.
- **`pkg/mcp.NewSTDIO` registers no audit or authz middleware** — no production caller today, but exported.
